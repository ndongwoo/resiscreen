# 마일스톤 2 보고: 엔진, 구조·기간 검사, Node CLI (2026-11-26)

> 공개용 판: 익명화 파일의 셀 원문 값(이름·제목·저널명·숫자 값)은 위치만 남기고 지웠다. 원문이 들어간 원래 판은 비공개 `docs/private/`에 있다.

> 공개 저장소용 문서. 병원은 A~F 기호로만 쓰고 셀 값·인명은 적지 않는다.

## 1. 한 일

- `src/engine/` (DOM 의존 없음)
  - `xlsx/xml.ts`: 직접 만든 XML 파서. Web Worker에는 DOMParser가 없어서 직접 만들었다. DTD·외부 엔티티는 해석하지 않고 줄 끝을 정규화한다.
  - `xlsx/workbook.ts`: JSZip으로 압축을 푸는 xlsx 읽기. 지원하는 것:
    - 공유·인라인·서식 있는 문자열, `_xHHHH_` 이스케이프
    - 날짜 시리얼(1900·1904 체계), 수식의 저장값, 공유 수식 전개
    - 병합 셀, 하이퍼링크(목록만 만들고 호출하지 않음), oleObject 앵커 셀 위치
    - 매크로·zip 폭탄 거부
  - `rules.ts`·`schema.ts`: 규칙 JSON 로딩, 스키마 검증(라이브러리 없이 직접 구현), 실행.
    - 한 규칙이 실패해도 나머지 규칙은 계속 돈다.
    - 한 시트에서 행 단위 결과가 10건을 넘으면 1건으로 묶는다.
  - `checks/`: `structure`(필수 칸·형식·수식 훼손·합계), `period`, `clinical`(행 수·과락·같은 환자·이름 가림), `staffing`(A-2-2, B-5, C-4), `evidence`, `activity`(B-2-3). `papers`는 마일스톤 4용 빈 틀이다.
  - `export.ts`: '점검결과' 엑셀(요약 + 결과 목록, 원본은 다시 저장하지 않음)과 결과 비교용 정렬 JSON.
- `src/cli/index.ts`: `resiscreen check <파일들> --out <폴더>`. 결과 JSON과 '점검결과' 엑셀을 만든다. ERROR가 있으면 종료 코드 1.
- `rules/2026.json`(규칙 34개, 활성 32개), `rules/schema.json`, `data/forms/2026_formulas.json`(자동계산 칸 위치. 수식 위치만 담고 값은 없음).
- `tools/`: `eval_recall`, `bench_read`, `make_synthetic`, `validate_rules`, `check_fixture_paths`.
- `tests/fixtures/synthetic/`: 합성 샘플 2개(완성본, 오류 포함본).
- 마일스톤 3 범위(진료·인원 검사)도 규칙이 이미 정리되어 있어 이번에 함께 구현했다. 마일스톤 3에서는 학회 답변을 반영하고 재현율을 보강한다.

## 2. 엑셀 읽기 방식 확정: 직접 XML 파서 + JSZip (ExcelJS는 결과 엑셀 생성에만 사용)

같은 PC(Node 22)에서 같은 파일을 방식마다 따로 실행해 2회 측정했다.

| 파일 | 크기 | 직접 파서 | ExcelJS |
|---|---|---|---|
| A | 23.9MB | 140ms / 최대 메모리 139MB | 891ms / 282MB |
| D | 47.8MB | 177ms / 152MB | 1,175ms / 421MB |
| E | 8.1MB | 141ms / 131MB | 538ms / 255MB |
| F(평가전) | 1.1MB | 108ms / 106MB | 341ms / 210MB |

- 속도는 3~7배 빠르고 메모리는 절반이다. 임베디드 PDF를 풀지 않고 위치만 읽기 때문이다.
- 첨부 셀 위치: ExcelJS는 oleObject 앵커를 주지 않는다. 직접 파서는 A 24개, D 48개를 모두 읽었다.
- 값 일치: 11개 파일에서 ExcelJS가 돌려준 비어 있지 않은 셀 약 10만 개를 비교했다(병합 셀의 복사본 제외).
  - 처음에는 줄바꿈(CRLF) 정규화가 빠져 평가전 파일에서 약 360칸이 달랐다. 고친 뒤 테스트를 추가했다.
  - 남은 차이는 파일당 1칸이다. 텍스트형 수식 결과에 날짜 서식이 붙은 칸을 ExcelJS가 Date로 바꾸는 경우이고, 직접 파서가 XML 원문과 맞다.
- SheetJS는 필요 없다고 판단한다.
- 엔진 전체(읽기 + 규칙) 처리 시간은 파일당 0.1~0.2초다(논문 조회 제외, Node 기준). 브라우저 측정은 마일스톤 5에서 한다.

4. A-2-2
   - 양식 J4 문구 전문: "평가 전년도 2025년 9/30일 기준 전공의 정원(n) 대비 정원책정 지도전문의(N)수가 n ≤ N-3를 충족하는가? * 이동수련자 제외한 최다 연차의 전공의 수 적용"
   - 계산에 쓰는 칸: N = 전체!I6. n은 두 가지로 계산한다. (1) max('A-3-2'!B4:B7), (2) 'A-3-2'!B9(정원 합계).
   - 선택값이 두 해석 모두와 다르면 WARNING을 낸다. 두 해석의 결론이 서로 다르면 두 값을 모두 담은 INFO를 낸다. `todo`는 그대로 둔다.
   - 실측(A~E, 모두 '충족' 선택): 다섯 병원 모두 해석 (1)로 계산하면 '충족', 해석 (2)로 계산하면 '미충족'이었다(병원별 N·n 값은 비공개 문서에 둠).

5. FX7: FV6=0이고 빈칸이면 "'해당없음'을 선택하세요" WARNING(`S-FX7-NA`), FV6>0이고 빈칸이면 ERROR(`S-REQ-SEL-COND2`). 그래서 A병원 WARNING이 2건이 되었다. GH6·CW7·평가위원·실사 칸 제외는 그대로 두고 `docs/OPEN_QUESTIONS.md`(학회 확인 필요 목록)에 넣었다.
