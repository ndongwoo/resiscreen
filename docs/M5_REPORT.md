## 1. 한 일

- `index.html`
  - 안내 문구(작업 지시 2절 원문 그대로)와 함께 '제목으로 조회하며 병원명·저자·환자 정보는 보내지 않는다'는 설명을 넣었다.
  - CSP 메타 태그: `default-src 'none'; script-src 'self'; worker-src 'self'; style-src 'self'; connect-src https://api.crossref.org https://eutils.ncbi.nlm.nih.gov` 등. `referrer` 정책은 no-referrer.

  - 조회는 쿠키 없이(`credentials: 'omit'`) 보낸다.
- `src/web/main.ts`, `ui.ts`, `style.css`
  - 파일 선택(드래그 앤 드롭 포함). 150MB를 넘는 파일은 확인 창을 띄운다(`reference.large_file_mb`).
  - 외부 서지 조회 체크박스(기본 켜짐).
  - SCIE 목록 불러오기와 삭제: IndexedDB `resiscreen/journals`에 저장하고, 저장했다는 사실과 공용 PC 안내를 화면에 보인다.
  - 서지 조회 캐시 지우기.
  - 단계별 진행(읽기 → 구조 검사 → 논문 조회 n/N → 완료)과 논문 조회 취소.
  - 결과 요약: 단계별 건수, 양식 연도, 규칙 상태, 조회 성공·실패. Crossref·PubMed별로 찾음·없음·실패·재시도(사유)·캐시 적중을 표로 보인다.
  - 단계 필터, 시트별 결과 표(단계·위치·항목·설명·근거·규칙).
  - 내려받기: '점검결과' 엑셀(Worker에서 만듦, 원본은 다시 저장하지 않음), 인쇄용 HTML(스크립트 없음, 자체 CSP), 브라우저 인쇄(인쇄용 CSS).
  - 다크 모드, 좁은 화면 대응.
- localStorage·sessionStorage는 쓰지 않는다. 실측에서 IndexedDB 저장소는 `biblio`와 `journals` 두 개뿐이었다.

### 1.1 보안 보강: Worker는 페이지 CSP를 따르지 않는다
`<meta>` CSP는 문서에만 적용된다. Web Worker의 CSP는 Worker 스크립트의 응답 헤더로 정해지는데, GitHub Pages는 응답 헤더를 바꿀 수 없다. 그래서 Worker 안의 요청은 메타 CSP로 막히지 않는다.

- 엔진의 요청 계층(`throttle.ts`)에 허용 호스트 목록을 넣었다. `api.crossref.org`, `eutils.ncbi.nlm.nih.gov`이고 https와 443 포트만 허용한다.
- 목록 밖의 주소는 요청 자체를 보내지 않는다.
- CSP `connect-src`와 이 목록이 같은지 테스트로 확인한다(`tests/unit/web.test.ts`).

## 2. 실제 브라우저 확인

- 환경: 연결된 Chrome(Windows PC). 이 PC는 개발 서버(리눅스)의 localhost·사설 IP에 접속할 수 없었다.
- 그래서 개발자(남동우) 승인(2026-11-26)을 받아 Cloudflare 임시 터널(`https://*.trycloudflare.com`)로 빌드 결과(`dist/`)만 잠시 공개했다. 확인 후 바로 껐다.
  - github.io처럼 HTTPS의 다른 출처라서 CORS 조건이 같다.
  - 병원 파일은 터널로 올리지 않았다. 테스트 파일은 브라우저에 직접 넣어 그 안에서만 처리했다.
- 파일 넣기 도구의 크기 제한(10MB) 때문에 실데이터는 E병원(8.1MB)으로 확인했다.

**확인하지 못한 것**
- **Edge**: 연결된 브라우저가 Chrome 하나뿐이다. Chromium 엔진이 같아 같은 동작이 예상되지만 실측은 아니다. GitHub Pages 배포(마일스톤 6) 뒤 Edge에서 확인하겠다.
- **인쇄 창과 150MB 확인 창**: 브라우저 모달 창이라 자동화 도구로 누르지 않았다. 코드상 `window.print()`와 `confirm()`을 쓴다.
- **브라우저에서 네트워크를 끈 상태**: 자동화 도구로 오프라인을 흉내 낼 수 없었다. 엔진 테스트('네트워크가 끊긴 상태(A병원)')로 확인했고, 브라우저에서도 같은 엔진이 돈다.
- **25MB 이상 파일(A·B·C·D)의 브라우저 처리 시간**: 파일 넣기 도구 제한 때문에 못 쟀다. Node 기준으로는 읽기와 규칙 검사가 0.2초, 조회는 D(23편) 기준 첫 실행 21.6초다.

- **공개 전 점검과 이력 정리**
  - 이전 커밋 이력에서 다음이 발견되었다: 익명화 파일에서 온 논문 제목 일부, 가명 이름, 셀 값, 심사 의견 원문, 개인 이메일. 들어간 곳은 테스트 예시 문자열, 공개 문서의 표와 설명, 규칙 파일의 예시·근거 문구였다. 실제 병원명, 심사위원 이름, 병원 엑셀 파일은 없었다.
  - 테스트와 도구의 문자열은 누가 봐도 합성인 값으로 바꾸고 합성 샘플을 다시 만들었다. 공개 문서는 위치만 남겼고, 원문이 들어간 원래 문서는 비공개 `docs/private/`로 옮겼다.
  - 원래 이력은 저장소 밖의 비공개 번들로 백업했다. 공개용 저장소는 정리된 파일로 만든 새 첫 커밋 하나로 다시 시작했다.
  - 같은 검사를 `npm run scan:private`(`tools/prepublish_scan.ts`)로 만들어 push 전 필수 단계로 두었다(README '배포 절차').
