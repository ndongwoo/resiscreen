## 2. ResiReview에서 옮길 로직 (TypeScript 재작성 대상)

### 2.1 엑셀 파서 (`engine/ooxml.py`, 440줄)
- openpyxl 없이 OOXML을 직접 읽음: sharedStrings, 공유 수식(shared formula) 전개, 캐시값과 리터럴 구분, 오류값, 서식 서명, 병합, 데이터 유효성.
- 방어: zip 항목 5000개, 압축 해제 총량 400MB, 압축비 300배 초과 시 거부.
- 첨부: `xl/embeddings/*`를 **시트 단위로만** 연결(셀 위치 없음) → 새 엔진은 시트 XML의 `<oleObject><objectPr><anchor><from>`을 읽어 셀 위치까지 연결해야 함(실측 확인: `논문` 시트 첨부는 T열·각 논문 행에 앵커됨).
- 외부 링크(`xl/externalLinks`)는 목록만 수집(A병원 파일에도 10개 존재 → 실행 금지 원칙 유지).

### 2.2 서지 조회·대조 (`surveys/bibliography_client.py`, `engine/bibliography*.py` v3.3~v3.8)
- **정규화** `norm`: NFKC → casefold → 영숫자 외 공백 치환. **제목 유사도**: difflib `SequenceMatcher.ratio() ≥ 0.90` → JS로 Ratcliff/Obershelp를 직접 구현(외부 라이브러리 불필요).
- **DOI 정규화·검증**: `doi:`/`https://doi.org/` 접두 제거, `10.\d{4,9}/...`.
- **저널 일치**: ISSN 교집합 → 괄호·부제 제거 후 핵심명 일치 → 단어별 약어 일치(Clin Exp Otorhinolaryngol 같은 ISO 약어 대응).
- **정식 출판일 판정**(v3.5 `formal_date`): print_date → (aheadofprint가 아니면) issue_date → 권 + (쪽 또는 논문번호)가 있으면 온라인 전용 발행일. Crossref의 일반 `published`만으로는 정식 출판으로 보지 않음.
- **기재 출판일 해석**: `2025.05`, `2025-05-07`, `2025년 5월` 등 명시적 4자리 연도만 인정, 연도 추정 안 함.
- **Epub 판별**: 일치한 모든 출처에 권·호·쪽·논문번호·인쇄일이 없고 online_date만 있으면 선출판 의심.
- **논문 형식**: Crossref `type`, PubMed `PublicationType`에서 letter/editorial/comment 탐지(v3.8).
- **PubMed 파싱**: esearch(DOI→[DOI], 없으면 [Title]) → efetch XML. `PubDate`의 `MedlineDate`, 월 약어 처리.
- **후보 여러 개**는 오류(ambiguous)로 두고 확정하지 않음.
- **전송 정책**: 허용 호스트 2개(api.crossref.org, eutils.ncbi.nlm.nih.gov), 요청 간격 ≥0.5초, 429/5xx는 Retry-After 또는 지수 백오프로 최대 3회.
- ResiReview는 서버 프록시를 거쳤음 → 새 도구는 아래 CORS 실측에 따라 브라우저에서 직접 호출.

  - `i 두경부양성`: E=진단명, F=수술명, G=필요시 병리 소견.

  - **DOI·PMID 열이 없음(11개 파일 모두)** → 제목 검색이 기본 경로.
- 첨부: 파일당 임베디드 13~48개(대부분 `Acrobat Document` oleObject, 일부 내장 xlsx). 하이퍼링크는 시트 이동용 내부 링크가 대부분.
- 파일 크기 1~50MB. 표준 라이브러리 파서로 11개를 모두 읽는 데 약 1초.

## 4. CORS 실측 (curl, `Origin: https://<임의>.github.io` 헤더로 단순 GET)

| API | 결과 |
|---|---|
| Crossref `/works/{doi}` | 200, `Access-Control-Allow-Origin: *`, 404에도 ACAO 있음. 한도 10건/초 |
| Crossref `/works?query.bibliographic=` | 200, ACAO `*`, **한도 3건/초**. 연속 호출 시 429가 나왔고 **429 응답에는 ACAO 헤더가 없음** → 브라우저에서는 상태코드를 못 읽고 네트워크 오류로 보임 |

| Europe PMC REST | 이 서버 네트워크에서 30초 타임아웃(2회). 판정 보류 |

결론: Crossref와 PubMed는 브라우저에서 직접 호출할 수 있다. 실제 Chrome에서 github.io 도메인으로 다시 확인하는 일은 마일스톤 5의 배포 확인 항목으로 둔다. CSP `connect-src`는 `https://api.crossref.org https://eutils.ncbi.nlm.nih.gov` 두 개로 시작한다.

## 7.1 2027 양식에 DOI(또는 PMID) 열을 넣자는 건의 근거
2026 양식의 논문 시트에는 DOI·PMID 열이 없다(11개 파일 모두 확인). 그래서 자동 서지 확인은 제목 검색에 기댈 수밖에 없다. 제목 검색은 세 경우에 한 논문을 확정하지 못한다.
- 비슷한 제목의 논문이 여럿 있을 때
- 제출자가 제목을 줄이거나 오타를 냈을 때
- 국문 제목처럼 Crossref·PubMed 색인이 약할 때

이때는 사람이 직접 찾아봐야 한다. 실제로 ResiReview 개발 과정에서 '일치 후보 여러 개', '저널 미확인' 결과가 따로 생겼다. 반면 DOI는 Crossref에서 바로 한 건으로 풀리고, 정식 출판일·권·호·쪽·논문 유형을 그대로 받아 올 수 있다. 그러면 Epub 여부, 출판연도, Letter 여부를 확인하는 일이 대부분 자동이 된다. DOI가 없는 국내지는 PMID 또는 'DOI 없음' 표기로 대신하게 하면 된다. 제출 병원 입장에서도 논문 표지에 이미 적힌 값을 옮겨 적기만 하면 되므로 부담이 작고, 서류심사에서 제목 대조와 표지 PDF 확인에 드는 시간이 줄어든다.

## 7.2 개발자(남동우) 판단 반영(2026-11-26, 학회 확인 필요)
- 서지: 제목 검색이 기본이고 DOI가 있으면 DOI를 먼저 쓴다. 확신도 기준(제목 유사도 ≥ 0.90 + 연도 일치 + 저널 일치)에 못 미치면 'WARNING: 자동 확인 불가(후보 논문 표시)'로 낸다. PubMed esearch(제목)와 Crossref를 함께 쓰고, 국내지는 Crossref를 먼저 쓴다. Europe PMC는 쓰지 않는다.
- 요청은 초당 2건 이하로 보낸다. 네트워크 오류는 429일 수 있다고 보고 지수 백오프로 최대 3회 다시 시도한 뒤에만 '확인 불가'로 처리한다. mailto는 설정값이다.
- C-4 분자는 논문 점수, B-6은 `enabled:false`. A-2-2 N-3 식은 양식 J4 문구에서 찾았다. 숫자 칸에 글자가 있으면, 그 칸을 다른 수식이 참조할 때 ERROR, 아니면 WARNING.

## 7.3 F병원 쌍에 대한 ResiReview의 해석
ResiReview 문서(`docs/guideline-2026-changes.txt`)는 F 쌍을 "학회가 I6·J6/J7 빈칸을 채운 것"으로 보고 평가 전·후 쌍으로 다뤘다. 하지만 심사 의견이 말하는 '7행에 잘못 적힌 숫자'가 평가전 파일에 없으므로, 이 저장소에서는 개발자(남동우) 판단, 학회 확인 필요에 따라 재현율 평가에서 뺀다.
